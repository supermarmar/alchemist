9. How the phase ran

The run was subagent-driven: a fresh Sonnet implementer per task, a task review of spec and quality after each, up to three fix rounds, a whole-branch review at the end, and one fix wave. Twenty transcription agents ran in two batches with the coordinator on Opus. Seventeen specifications the coordinator wrote were wrong and were caught before shipping, one excepted; the report records all seventeen and the four checks that came out of them, and the grouping below is this page's.

  • Seven were tests that passed for a reason other than the one they named. The cure that held was making the implementer inject the named bug and report whether the test went red.
  • Four were verification commands that could never fail: a self-check reading the wrong directory, a zsh abort on an empty glob, an unguarded YAML load, and a collision scan that could not see nodes/.
  • Three were facts stated from memory: both ASSA papers described as general insurance, a fabricated SP7 anchor, and a README template sentence false on the day it shipped.
  • Two were counts the plan kept from an earlier moment: 23 bodies against 20, and three non-existent node ids in the gap ledger.
  • One shipped: a head figure counting anchor entries under a label saying bodies, 405 against 240, passed every task review because its one fixture agreed both ways. The whole-branch review found it.

Four pre-dispatch checks now run on every brief before an implementer sees it: grep for banned constructions and dashes, grep every count word against the current measurement, execute every verification command against a fixture built to fail it, and read every body-specific fact off the manifest. Two harness quirks cost time and lost nothing: the API session limit killed all nine Batch B agents and Task 14 before any wrote a file, and the harness refused every subagent write of a file named report.md, so eleven of the 21 transcription reports were written to disk by the coordinator from returned text, each with a provenance header.
